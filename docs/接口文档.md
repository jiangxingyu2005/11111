# 检索服务接口文档（retrieval · 端口 8100）

> 本文档是 retrieval 服务（独立于 qingxi 主服务 8001）**全部 HTTP 接口**的唯一入口，一份看完。
> Base URL = `http://<host>:8100`。
>
> 前端主交互只有一个接口：`POST /api/retrieval`（SSE 流式问答）。多轮对话上下文靠请求里的
> `session_id` + `token` 两个字段驱动，会话的增删改查由独立接口 `/api/sessions` 提供。
>
> 关联参考（非接口，用到再查）：[接入自有模型.md](../retrieval/docs/接入自有模型.md)（换 embed/rerank/LLM）｜
> [qingxi接口.md](../retrieval/docs/qingxi接口.md)（切 real 通道连 qingxi 入库产物的字段对齐清单）。

---

## 0. 端点总览

| 接口 | 方法 | 用途 |
|---|---|---|
| `/healthz` | GET | 健康检查 |
| `/api/retrieval` | POST | **问答主接口**（SSE 流式，见 §1） |
| `/api/sessions` | POST / GET | 创建会话 / 列出我的会话（见 §2） |
| `/api/sessions/{session_id}` | PATCH / DELETE | 重命名 / 删除会话（见 §2） |
| `/api/sessions/{session_id}/messages` | GET | 查看会话消息历史（见 §2） |
| `/api/graph/subgraph` | GET | 答案关联图谱（见 §4） |
| `/api/eval/benchmark` | POST | 离线测评：召回率 + 响应时间（见 §5） |

### 通用约定

- **认证**：无（内网服务）。会话管理接口额外要求 `Authorization: Bearer <token>`（见 §2）。
- **`scope`**：知识库 id 列表，所有检索相关接口都按它过滤 `kb_id`，必填无默认值（权限硬约束）。
- **fail-closed**：记忆 / 图谱 / 生成等旁路失败只降级、不报错、不拖主链；降级必进 `degraded[]`。
- **SSE 兜底**：主链任何未捕获异常发 `error` 事件（而非 HTTP 5xx）。

## 1. 问答接口 `POST /api/retrieval`

### 1.1 请求契约

```json
{
  "query": "AN/TPY-2 工作在什么频段",
  "scope": ["kb_public"],
  "session_id": "sess-8f14e45f",
  "token": "u_001",
  "eval_mode": false
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `query` | string | **是** | 自然语言问题（min_length=1） |
| `scope` | string[] | **是** | 知识库范围（R4：必填无默认值，权限硬约束，见 §1.2） |
| `session_id` | string? | 否 | 会话 id；缺省时记忆层落到 `"default"` 会话（见 §3） |
| `token` | string? | 否 | 记忆身份令牌；缺省/解析失败 = 本轮跳过记忆（见 §3） |
| `eval_mode` | bool | 否 | 评测模式（不写缓存/不计被引），默认 `false`，前端保持 `false` |

### 1.2 `scope` 取值（最容易踩的坑）

`scope` 是**知识库 id 列表**，服务端按它过滤 Milvus/Neo4j 的 `kb_id` 字段。当前 real 通道种子数据用的是
**固定字符串** `kb_public` / `kb_internal`：

| 场景 | scope 取值 |
|---|---|
| 内置种子数据（当前可跑） | `["kb_public"]` 或 `["kb_public", "kb_internal"]` |
| 切 real 连 qingxi 入库产物后 | qingxi 的知识库 UUID（见 [qingxi接口.md](../retrieval/docs/qingxi接口.md)） |

> ⚠️ **不是 qingxi 主服务（8001）的 `kb_id` UUID。** 传错 scope（如 `["dc0443e1-..."]`）不会报错，
> 而是所有路召回恒为 0 —— 这是最隐蔽的「静默查空」。先用 `curl` 传 `kb_public` 验证链路，再对前端。

### 1.3 响应（SSE 流）

响应头 `Content-Type: text/event-stream`。事件序列固定：

```
meta → progress(understand) → progress(recall) → results → rules → assets → token×N → done
```

任何一步主链异常都会在最后发 `error` 事件（而非 HTTP 5xx）。

| 事件 | `data` 关键字段 | 含义 |
|---|---|---|
| `meta` | `contract_version` `trace_id` `eval_mode` | 本次检索身份（`trace_id` 后续调子图要用） |
| `progress` | `stage` + 各阶段字段 | 检索步骤进度（`understand` / `recall`） |
| `results` | `hits[]` `degraded[]` | 最终证据列表（父块全文 + 子块锚点 + 分数） |
| `rules` | `hits[]` | 预设推理规则触发详情（空数组 = 未命中，不算降级） |
| `assets` | `items[]` | 资产/附件（当前恒空，IF-5 未就位） |
| `token` | `text` | **流式答案增量**（逐 token，直接拼接展示） |
| `done` | `meta` `graph_ref` `degraded` `timings` | 正常结束 + 汇总 |
| `error` | `message` `degraded` | 失败兜底（含降级码） |

`progress` 的 `stage` 取值：

| stage | 字段 | 含义 |
|---|---|---|
| `understand` | `intent` `conditions[]` | 查询意图 + 结构化条件（可空） |
| `recall` | `vector` `bm25` `graph` `community` `budget_level` | 各路召回命中数 + 当前预算档位 |

### 1.4 关键事件字段明细

**`results.hits[]`**（每条证据）：

```json
{
  "parent_id": "p_doc_0012",
  "child_id": "c_00066",
  "title": "西部高原C驱逐舰载AN/SPS-49测高雷达信号侦察记录（2025年3月15日）",
  "content": "父块全文（可直接展示的原文片段）…",
  "metadata": {"kb_id": "kb_public", "voted_by": ["vector_hybrid"], "rank": 1,
               "via_entity": null, "via_community": null},
  "evidence": {"child_id": "c_00066", "span": [0, 0]},
  "score": {"rrf": 0.033, "rerank": 0.82}
}
```

- `content` 是**父块全文**（已回捞，可直接渲染）；`evidence.span` 是原文高亮锚点（IF-2 未就位时可能为 `null`/`[0,0]`）。
- `score.rerank` 为 0~1 置信度（重排超时时退化为 `rrf` 序，`rerank` 字段为 `null`）。

**`done`**：

```json
{
  "contract_version": "1.0",
  "trace_id": "fd10cd5d...",
  "meta": {"intent": "ENTITY_LEVEL", "query_rewritten": null, "conditions": []},
  "graph_ref": {
    "available": true,
    "focus_entities": ["ent_02829071", "…"],
    "endpoint": "/api/graph/subgraph",
    "binding": "trace_id",
    "default_hops": 1, "node_limit": 50, "edge_limit": 100
  },
  "degraded": [],
  "timings": {"parse_ms": 1, "vector_ms": 120, "rerank_ms": 800, "pg_fetch_ms": 20,
              "first_token_ms": 950, "total_ms": 2100},
  "budget_level": "L4",
  "rule_hits": []
}
```

- `graph_ref.available=true` 时，前端可用 `trace_id` 调 `GET /api/graph/subgraph` 画答案关联图谱（见 §4）。
- `timings` 供前端展示各阶段耗时；`degraded` 是降级明细（空 = 全链路无降级）。

### 1.5 前端对接代码（fetch 读流）

> 接口是 **POST**，浏览器 `EventSource` 只支持 GET，必须用 `fetch` + `ReadableStream` 读流。

```js
// SSE 解析：把字节流切成 event/data 块
function makeSSEParser(onEvent) {
  let buf = '';
  return chunk => {
    buf += chunk;
    let idx;
    while ((idx = buf.indexOf('\n\n')) !== -1) {
      const block = buf.slice(0, idx);
      buf = buf.slice(idx + 2);
      let event = 'message', data = '';
      for (const line of block.split('\n')) {
        if (line.startsWith('event:')) event = line.slice(6).trim();
        else if (line.startsWith('data:')) data += line.slice(5).trim();
      }
      if (data && data !== '[DONE]') {
        try { onEvent(event, JSON.parse(data)); } catch (e) { /* 忽略脏帧 */ }
      }
    }
  };
}

async function ask({ query, scope = ['kb_public'], sessionId, token,
                     onStep, onHits, onToken, onDone, onError } = {}) {
  const resp = await fetch('/api/retrieval', {
    method: 'POST',
    headers: { 'content-type': 'application/json' },
    body: JSON.stringify({ query, scope, session_id: sessionId, token }),
  });
  if (!resp.ok || !resp.body) throw new Error('HTTP ' + resp.status);

  const feed = makeSSEParser((event, p) => {
    switch (event) {
      case 'progress': onStep?.(p); break;
      case 'results':  onHits?.(p.hits); break;
      case 'token':    onToken?.(p.text); break;   // 流式答案增量
      case 'done':     onDone?.(p); break;
      case 'error':    onError?.(p); break;
    }
  });

  const reader = resp.body.getReader();
  const dec = new TextDecoder();
  while (true) {
    const { done, value } = await reader.read();
    if (done) break;
    feed(dec.decode(value, { stream: true }));
  }
}

// 用法：逐 token 渲染答案 + 结束时拿 trace_id 调子图
let answer = '';
await ask({
  query: 'AN/TPY-2 工作在什么频段',
  scope: ['kb_public'],
  sessionId: 'sess-demo', token: 'u_001',
  onStep: p => console.log(p.stage, p),
  onHits: hits => renderEvidence(hits),
  onToken: t => { answer += t; renderAnswer(answer); },
  onDone: d => d.graph_ref.available && renderGraph(d.trace_id, d.graph_ref),
  onError: e => console.error(e),
});
```

## 2. 会话管理 `/api/sessions`（独立 CRUD）

前端传身份 `Authorization: Bearer <token>`（token 解析出 user_id，与记忆层同源），会话按
`(user_id, session_id)` 隔离。**该接口独立于 `MEMORY_ENABLED`，始终可用。**

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/sessions` | 创建会话（`session_id` 缺省则服务端生成；已存在返回 409） |
| GET | `/api/sessions` | 列出当前用户全部会话（最近更新倒序，含消息数） |
| GET | `/api/sessions/{session_id}/messages` | 查看某会话消息历史（`?limit=` 默认 200，1~1000） |
| PATCH | `/api/sessions/{session_id}` | 重命名会话（改标题） |
| DELETE | `/api/sessions/{session_id}` | 删除会话（级联删消息） |

请求/响应示例（`token` = 前端登录后的用户身份，passthrough 模式即 user_id）：

```js
// 创建（前端记住返回的 session_id，问答时传回 /api/retrieval）
const s = await fetch('/api/sessions', {
  method: 'POST',
  headers: { 'Authorization': 'Bearer u_001', 'Content-Type': 'application/json' },
  body: JSON.stringify({ title: '雷达频段调研' }),
}).then(r => r.json());            // {session_id:"...", title:"...", created_at:"...", updated_at:"..."}

// 列出我的会话
await fetch('/api/sessions', { headers: { 'Authorization': 'Bearer u_001' } });
// → {"sessions": [{session_id, title, message_count, created_at, updated_at}, ...]}

// 查历史消息
await fetch(`/api/sessions/${s.session_id}/messages`, {
  headers: { 'Authorization': 'Bearer u_001' },
});
// → {"session_id":"...", "messages":[{role, content, created_at}, ...]}

// 重命名
await fetch(`/api/sessions/${s.session_id}`, {
  method: 'PATCH',
  headers: { 'Authorization': 'Bearer u_001', 'Content-Type': 'application/json' },
  body: JSON.stringify({ title: '新标题' }),
});
// → {"session_id":"...", "title":"新标题"}

// 删除
await fetch(`/api/sessions/${s.session_id}`, {
  method: 'DELETE', headers: { 'Authorization': 'Bearer u_001' },
});
// → {"deleted": true, "session_id":"..."}
```

**身份与隔离**：
- 无 token / 解析失败 → `401`（会话管理必须有身份才能隔离，不做静默降级）。
- 每个用户只能看到/操作自己的会话；越权访问他人 `session_id` 返回 `404`（不泄露存在性）。
- 创建已存在的 `session_id` → `409`。
- token 解析规则同记忆层：`passthrough`（token 即 user_id）或 `jwt`（验签 sub），由 `MEMORY_AUTH_MODE` 决定。

**与问答接口的关系**：`POST /api/sessions` 拿到的 `session_id` 传给 `POST /api/retrieval` 的
`session_id` 字段，问答产生的消息落到同一会话。注意问答的记忆写回受 `MEMORY_ENABLED` 控制——
要让 `GET .../messages` 能看到问答历史，需开 `MEMORY_ENABLED=true`。

## 3. 会话上下文与记忆（多轮对话）

多轮对话的「上下文」由服务端记忆层负责，前端只需**每次请求都带上** `session_id` + `token`，
服务端自动装载历史并写回本轮，前端无需自行维护对话数组。

### 3.1 两个字段怎么用

| 字段 | 作用 | 取值建议 |
|---|---|---|
| `token` | 解析出 `user_id`，**跨会话**隔离用户 | passthrough 模式：直接传用户 id（如 `"u_001"`）；jwt 模式：传签发的 HS256 令牌 |
| `session_id` | 在 `user_id` 下**再按会话**隔离 | 前端生成并持久化一个会话 uuid，同一用户多开会话互不串 |

隔离键 = `(user_id, session_id)`。两个不同 `token` 之间互不可见；同一 `token` 下不同 `session_id` 是不同会话。

### 3.2 上下文装了什么

服务端生成答案前装载三层上下文，**注入到 LLM 提示词里帮助理解指代与背景**（但历史不是证据，
结论仍须由检索出的 `[n]` 证据支撑）：

| 层 | 存哪 | 作用 |
|---|---|---|
| **窗口 window** | PG `messages` 表 | 最近 N 轮原文（默认 10 条） |
| **摘要 summary** | PG `conversations` 表 | 递归压缩的会话摘要（token 触发压缩） |
| **事实 memories** | mem0 → Milvus `mem0_memory` | 长期事实（跨会话可召回，检索 top3） |

压缩流水线（按 token 用量触发，不按条数）：先 `memory.add` 把被挤出的原文抽进 mem0（失败则整体放弃、
保留原文），再递归摘要，最后裁剪窗口；压缩次数封顶后只留最新窗口条数。**任一步失败都保留原文、
放弃本次压缩，绝不阻断检索主链。**

### 3.3 开关与身份模式

记忆功能**默认关闭**（`MEMORY_ENABLED=false`），开启后在 `.env` 配：

| 变量 | 默认 | 说明 |
|---|---|---|
| `MEMORY_ENABLED` | `false` | 记忆总开关，置 `true` 开启 |
| `MEMORY_AUTH_MODE` | `passthrough` | `passthrough`（token 即 user_id）/ `jwt`（验签 sub） |
| `MEMORY_JWT_SECRET` | `` | jwt 模式验签密钥 |

算法参数（窗口大小 / 预算 / 触发比等）在 `config/retrieval.yaml` 的 `memory:` 段。

- **fail-closed**：`token` 缺失/解析失败 → 本轮跳过记忆，**主链照跑**，不影响问答。
- ⚠️ `passthrough` 是「自报身份」，只适合内网/测试；对外要隔离防伪必须切 `jwt` + 配 `MEMORY_JWT_SECRET`。
- mem0 是**进程内库**（复用 Milvus + 统一 LLM 接口 `app/llm.py`），不是独立服务，无需单独部署；
  LLM 配置复用 `GRAPHRAG_LLM_*`。

## 4. 关联图谱 `GET /api/graph/subgraph`

`done` 事件 `graph_ref.available=true` 时调用：

```
GET /api/graph/subgraph?trace_id=<done.trace_id>&scope=kb_public&hops=1
```

| 参数 | 必填 | 说明 |
|---|---|---|
| `trace_id` | 是 | 本次检索的 `trace_id`（服务端用它绑定的 focus 实体取子图，防前端篡改） |
| `scope` | 是 | 与检索时一致的 scope（服务端二次校验） |
| `hops` | 否 | 跳数 1~2，默认 1 |
| `entity_ids` / `relation_types` | 否 | 仅 trace 绑定过期时回退用 / 关系类型白名单过滤（未知类型 422） |

响应含 `nodes[]`（实体节点，`is_focus` 标记焦点）、`edges[]`（关系边，带 `type`/`confidence`/`evidence`）、
`meta`（节点/边计数、是否截断）、`degraded`。图谱慢/挂不影响检索结果渲染（独立降级）。

## 5. 离线测评 `POST /api/eval/benchmark`

> 这是**评测接口，不是问答接口**，不对最终用户开放。用途是「换模型 / 改阈值 / 改融合」前后的回归对比。

### 5.1 请求契约

```json
{
  "seed_dir": "data/seed_date",
  "max_per_type": 200,
  "ks": [5, 10, 20],
  "scope": ["kb_public"]
}
```

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `seed_dir` | string | `data/seed_date` | golden 评测集目录，**必须含 `chunks.json`**（缺失返回 400） |
| `max_per_type` | int | `200` | 每类 query 抽样上限（1~2000）；小样本取小值秒级返回 |
| `ks` | int[] | `[5,10,20]` | 召回率统计的 top-k 列表 |
| `scope` | string[] | `["kb_public"]` | 检索范围 |

**关键约定**：
- 测评在**进程内**强制 `RETRIEVAL_BACKEND=fake` + `RETRIEVAL_SEED_DIR=<seed_dir>` 跑全链路，不依赖
  Milvus/PG/Neo4j，跑完还原 env/缓存/单例，**不污染在线服务后续请求**。
- `data/seed_date` 由 `python scripts/ingest_date.py` 从真实 `date/` 数据结构化解析产出，**跑测评前须先执行一次**。
- 注意 `data/seed_date`（golden 评测集）与 fake 后端的运行时种子 `data/seed` 是两个目录，别混。

### 5.2 响应契约（节选）

```json
{
  "meta": {"seed_dir": "data/seed_date", "n_chunks": 130, "n_queries": 584,
           "max_per_type": 200, "ks": [5, 10, 20], "backend": "fake(hash embed, in-process)"},
  "test": {
    "final": {"crecall@5": 0.812, "recall@5": 0.940, "cprec@5": 0.677, "mrr": 0.861, "ndcg@10": 0.881},
    "fused": {"crecall@5": 0.740, "recall@5": 0.910, "mrr": 0.822},
    "latency": {"mean_ms": 320.1, "p50_ms": 298.0, "p90_ms": 445.0, "p95_ms": 501.2,
                 "p99_ms": 812.0, "max_ms": 1500.0, "over_budget": 3, "n": 467},
    "n_q": 467
  },
  "val": { "...": "结构与 test 相同" },
  "by_type": {"band": {"final": {...}, "fused": {...}, "latency": {...}, "n_q": 120, "hit_rate@5": 0.92}},
  "hit_rate@5": {"test": 0.91, "val": 0.89},
  "per_query": [
    {"q": "X波段 线性调频 雷达", "type": "band", "lat_ms": 301.2, "degraded": [],
     "gold_n": 3, "core_n": 2, "fused_n": 50,
     "final": [{"child_id": "c_00066", "parent_id": "p_doc_0012",
                "rerank_score": 0.88, "grade": 2, "snippet": "…"}]}
  ]
}
```

### 5.3 指标口径

| 指标 | 口径 |
|---|---|
| `crecall@k` | **核心召回**：top-k 命中 gold 里 `grade≥2`（核心命中）的比例 |
| `recall@k` | 召回：top-k 命中任意 gold 的比例 |
| `cprec@k` | 核心精度：top-k 里核心命中占 gold 核心的比例 |
| `mrr` / `ndcg@10` | 平均倒数排名 / 折损累计增益 |
| `hit_rate@5` | top-5 命中 ≥1 条核心 gold 的 query 占比 |
| `grade` | 每条命中的匹配度：`2`=核心命中 / `1`=相关 / `0`=未命中 |

> ⚠️ **口径红线**：本接口在 **hash 通道**下跑，`crecall` 等数字只能证明「链路通、逻辑对」，**不能当作真实
> 召回质量**。真实 BGE-M3 的召回质量验收要走 `python scripts/check_embed_space.py --expect real`
> （见 [接入自有模型.md](../retrieval/docs/接入自有模型.md)）。

## 7. 常见问题

- **召回恒为 0？** 先查 `scope` 是不是 `kb_public`/`kb_internal`（§1.2），不是 qingxi 的 UUID。
- **没有 `token` 事件（答案为空）？** `token` 依赖 LLM 生成；LLM 未配/超时会降级为无正文
  （证据仍在 `results` 事件），`done.degraded` 会带 `generation_unavailable`。检查 `GRAPHRAG_LLM_*`。
- **多轮对话不记得上下文？** 确认 `MEMORY_ENABLED=true`、请求带了 `token` + `session_id`；
  记忆是 fail-closed，缺失时静默跳过而非报错。
- **流式一直不结束？** `done` 是结束标志；异常会收 `error` 事件而非 HTTP 5xx。
- **`results` 里 `content` 是全文、`evidence.span` 为 null？** IF-2 未就位，前端不要做回原文高亮。
- **`/api/eval/benchmark` 返回 400？** `seed_dir` 下缺 `chunks.json`，先跑 `python scripts/ingest_date.py`。
