# 接入自有模型

> 目标：**不改动 retrieval 任何代码**，只靠配置把自有的嵌入 / 重排 / 生成模型接进来。

---

## 一、整体思路

对外接口形状是**固定不变**的，无论背后接的是 BGE-M3、TEI、vLLM 还是自研服务：

```
POST /embed               {texts, type}   -> {embeddings:[{dense, sparse}], dim, model}
POST /rerank              {query, texts}  -> {scores:[...], model}
POST /v1/chat/completions OpenAI 兼容      -> JSON 或 SSE 流
```

差异全部收敛到两个配置字段：

| 字段 | 作用 |
|---|---|
| `models.<kind>.backend` | 用**哪种实现**去连 |
| `endpoints.<kind>` | 连**哪里**、怎么取字段 |

三种协议：

| protocol | 适用 | 触发的 backend |
|---|---|---|
| `local` | 进程内加载 | `hash` `bge_m3` `bge` `hf` `echo` |
| `openai` | OpenAI 兼容 HTTP | `openai` |
| `generic` | 任意 HTTP + 字段路径映射 | `generic` |

---

## 二、三步接入

### 第 1 步：选 backend

```yaml
# config/retrieval.yaml
models:
  embed:  {backend: openai}     # 或 generic
  rerank: {backend: generic}
  llm:    {backend: openai}
```

### 第 2 步：填地址

```yaml
endpoints:
  embed:
    url: "http://10.0.0.5:8080/v1"     # openai 协议填到 /v1，会自动拼 /embeddings
    model: "bge-m3"
    api_key: "EMPTY"
    preset: "openai_embed"
  rerank:
    url: "http://10.0.0.5:8080/rerank" # generic 填完整路径
    model: "bge-reranker-v2-m3"
    preset: "tei_rerank"
  llm:
    url: "http://10.0.0.6:9000/v1"
    model: "qwen2.5-14b-instruct"
    api_key: "EMPTY"
```

> 不想改 yaml？用环境变量覆盖即可，优先级 **env > yaml**：
> `EMBED_BACKEND` / `EMBED_URL` / `EMBED_MODEL` / `EMBED_API_KEY` / `EMBED_PRESET`
> （rerank、llm 同理换成 `RERANK_*`、`LLM_*`）

### 第 3 步：先验再上线

```bash
# 拿到新地址，不写配置、不重启，直接验
python scripts/check_provider.py --kind embed  --url http://10.0.0.5:8080/v1 --preset openai_embed
python scripts/check_provider.py --kind rerank --url http://10.0.0.5:8080/rerank --preset tei_rerank
python scripts/check_provider.py --kind llm    --url http://10.0.0.6:9000/v1 --model qwen2.5-14b-instruct

# 写进配置后，自检当前生效配置
python scripts/check_provider.py

# 服务已起时，也可以直接问它（不重启）
curl -s http://127.0.0.1:8001/v1/model-info        # 看当前接的是什么
curl -s -X POST http://127.0.0.1:8001/v1/probe -H 'Content-Type: application/json' \
     -d '{"kind":"embed","url":"http://10.0.0.5:8080/v1","preset":"openai_embed"}'
```

## 三、现成预设（presets）

在 `endpoints.<kind>.preset` 填名字即可，不必手写字段映射。

| preset | 适用能力 | 请求 | 响应取值 |
|---|---|---|---|
| `openai_embed` | embed | `{model, input}` | `data.*.embedding` |
| `tei_embed` | embed | `{inputs:[...]}` | `*` |
| `ollama_embed` | embed | `{model, input:[...]}` | `embeddings.*` |
| `tei_rerank` | rerank | `{query, texts}` | `*.score` |
| `siliconflow_rerank` | rerank | `{model, query, documents}` | `results.*.relevance_score` |
| `local_bge_m3` | embed | 进程内 | — |
| `local_bge_reranker` | rerank | 进程内 | — |

**OpenAI 兼容**这一档覆盖面最广：vLLM、Xinference、OneAPI、llama.cpp server、ollama `/v1`、
SiliconFlow、以及大多数自研网关——这些直接用 `openai` 即可。

## 四、自研服务：手写字段映射

`generic` 协议靠两条路径适配任意 JSON：

```bash
python scripts/check_provider.py --kind embed --url http://my-svc/encode \
    --request-json  '{"texts_key":"sentences","model_key":"model"}' \
    --response-json '{"dense":"vectors.*","sparse":"lexical.*"}'
```

对应 yaml：

```yaml
endpoints:
  embed:
    backend: generic   # 写在 models.embed.backend
    url: "http://my-svc/encode"
    request:  {texts_key: sentences, model_key: model, extra: {normalize: true}}
    response: {dense: "vectors.*", sparse: "lexical.*"}
```

路径语法（点号分隔，`*` 表示对列表逐元素映射）：

| 响应 | 路径 | 结果 |
|---|---|---|
| `{"data":[{"embedding":[1,2]}]}` | `data.*.embedding` | `[[1,2]]` |
| `{"embeddings":[[1,2],[3,4]]}` | `embeddings.*` | `[[1,2],[3,4]]` |
| `{"vectors":[[1,2]]}` | `vectors.*` | `[[1,2]]` |
| `[{"index":0,"score":0.9}]` | `*.score` | `[0.9]` |
| `{"results":[{"relevance_score":0.8}]}` | `results.*.relevance_score` | `[0.8]` |

重排响应支持两种形状：`[0.9, 0.7]`（纯数值）或 `[{"index":0,"score":0.9}]`（带序号，
会按 index 回排保证与输入同序）。

## 五、接错了会怎样（这些是故意的硬失败）

| 情况 | 行为 | 为什么 |
|---|---|---|
| 嵌入维度 ≠ `models.embed.dim` | **直接报错** | 换模型忘了重建库 = 召回全是噪声且零报错，必须在接入那一刻就炸 |
| `backend` 要连外部但没填 url | **启动校验拦下** | 否则每个请求打空地址，配了模型却全失败 |
| 服务不返回 sparse | `sparse: null` | 绝不伪造空字典；此时应把 `milvus.sparse.enabled` 关掉 |
| 重排分数条数 ≠ 输入条数 | **报错** | 无法与候选对齐 |
| `real` 通道 + `hash` / `echo` | **拒绝启动** | E1 缺失是静默漂移，宁可停机 |

---

## 六、换模型必须做的三件事

改 `models.embed` 不只是改个字符串：

1. 改 `models.embed.id` / `dim` / `backend`
2. **重建 Milvus collection**（维度变了，旧向量全部失效）
3. **重跑 seed**：`python scripts/gen_seed.py --embed service`

然后 `python scripts/check_embed_space.py --expect real` 验收。

> 判别"真 BGE-M3 还是哈希占位"：**弱监督对的 Recall@5 不可信（哈希也能跑出 1.000）**，
> 要看 **Top1 余弦**（哈希 ≈ 0.45，BGE-M3 ≈ 0.85）和字面不重叠的硬案例。

## 七、本地 CPU 部署 LLM（ollama Q4 量化）

16GB 内存、无 GPU 的机器跑不动 3B 的 fp16/bf16（权重 6~12GB，首 token 数十秒），
本地化方案是 ollama 跑 Q4 量化（3B 仅 1.9GB，warm 后 ~4-5 tok/s）。

```bash
# 1. 装 ollama 并拉模型（GGUF Q4，存到 ollama 自己的 models 目录，不占 retrieval/model）
ollama serve                         # 默认监听 127.0.0.1:11434
ollama pull qwen2.5:3b

# 2. 配置（二选一）
#    a) config/retrieval.yaml
#       models.llm.backend = openai
#       endpoints.llm.url  = http://127.0.0.1:11434/v1
#       endpoints.llm.model = qwen2.5:3b
#    b) 或 .env 覆盖（retrieval 侧走 graphrag_llm_*，model_stub 侧走 LLM_*）
export GRAPHRAG_LLM_BASE_URL=http://127.0.0.1:11434/v1
export GRAPHRAG_LLM_MODEL=qwen2.5:3b

# 3. 自检（不重启）
python scripts/check_provider.py --kind llm --url http://127.0.0.1:11434/v1 --model qwen2.5:3b
```

ollama 的 `/v1` 是 OpenAI 兼容端点，`openai` 协议直接用；`endpoints.llm.model` 填的是
ollama 里的模型名（`qwen2.5:3b`），不是 HuggingFace 路径。

> **CPU 上的坑（已处理）**：① L2 结构化抽取（nl2query）与嵌入/重排（BGE-M3 + cross-encoder）
> 都吃 CPU。原先 L2 与召回并行起跑，16GB CPU 上互相争核 → 首查召回返空、重排 16s 撞
> `timeout.reranker_ms` 退化为 RRF 序、生成 first_token 70s+。**已修复：L2 起跑点串行化到
> 重排之后**（L2 结果只影响 `meta.conditions`、不影响召回，故可安全延后），与嵌入/重排完全
> 串行；另在启动期预热 ollama + Neo4j 连接。修后首查即零降级：rerank ~6-7s、first_token ~13s、
> total ~46s（原 100s）。② 报告生成（E2）与 L2 共用同一个 `graphrag_llm_base_url`，一旦指到
> ollama，生成也从模板 echo 变成真模型流式输出，长证据 prompt 的 prefill 在 CPU 上首 token
> warm ~13s / cold ~60s+。
> 生产 GPU 环境把 `models.llm.id` 换成 `qwen2.5-14b-instruct` 并指到 vLLM 即可。
